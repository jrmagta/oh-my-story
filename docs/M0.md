# M0 — Foundations: phase plan

Scope is the M0 row in `PLAN.md`. Each phase ends in a proof run against the real thing, and the next phase starts from that verified state.

## Defaults chosen (change any of these before the phase that uses them)

| Area | Choice | Why |
|---|---|---|
| Go module | `github.com/jrmagta/oh-my-story` | matches the repo |
| Go version | 1.26 | current stable |
| HTTP | stdlib `net/http` with the Go 1.22+ pattern mux | no router dependency needed yet |
| Postgres driver | `pgx/v5` with `pgxpool` | native Postgres features: LISTEN/NOTIFY, jsonb, COPY |
| Migrations | `goose`, SQL files embedded in the binary, run by `app migrate` | one binary, same command in compose and the Helm Job |
| Config | environment variables only, parsed once at startup into a typed struct | twelve-factor, simple in Helm |
| Passwords | argon2id | OWASP first choice |
| OIDC | `coreos/go-oidc` + `golang.org/x/oauth2` | standard, small |
| Containers | `docker compose` file that also runs under podman-compose | this machine uses podman |
| Tests | Go tests against a real Postgres from compose (`TEST_DATABASE_URL`), one fresh schema per test | `PLAN.md`: no mocked DB |

## Layout

```
cmd/oh-my-story/        main: subcommands serve | migrate
internal/config/        env → typed Config
internal/db/            pool, migrations (embed), test helpers
internal/db/migrations/ 0001_identity_and_workspaces.sql
internal/auth/          passwords, sessions, OIDC, middleware
internal/workspace/     workspaces, members, invites, roles
internal/httpapi/       handlers, routing, error shape
web/                    React + TS + Vite (phase 4)
deploy/compose/         docker-compose.yml, keycloak realm, Dockerfile
deploy/helm/oh-my-story/
.github/workflows/
```

## Phases

| # | Phase | Input state | Proof |
|---|---|---|---|
| 1 | **Skeleton and database.** Go module, config, `serve` with `/healthz`, goose runner, migration `0001` (users, identities, sessions, workspaces, workspace_members, invites per `DATA_MODEL.md`), compose with Postgres only, Makefile | docs only | `make test` passes against compose Postgres; `app migrate` applies `0001` and is a no-op on a second run; `/healthz` returns ok and reports DB reachable |
| 2 | **Full dev stack.** Dockerfile (static binary), compose adds app, Keycloak (imported realm + test user), Mailpit | phase 1 | `docker compose up` brings all four services healthy; `/healthz` ok through the app container; Keycloak realm and Mailpit UI reachable |
| 3 | **Auth and workspaces.** First-user bootstrap, local login (argon2id, session cookie), invites by email (lands in Mailpit), OIDC login against Keycloak, workspace CRUD, member roles, role-check middleware including comment-only | phase 2 | Go tests drive the HTTP API: bootstrap, login, invite, accept, OIDC round trip against Keycloak, and an authorisation matrix for the 5 roles |
| 4 | **Web shell.** Vite + React + TS, Tailwind with the design tokens, login, workspace list and members page, embedded in the binary | phase 3 | Playwright: sign in locally, sign in via Keycloak, invite a member, accept the invite from Mailpit |
| 5 | **CI.** GitHub Actions: Go tests with a Postgres service, lint, frontend build, Playwright | phase 4 | green run on a pull request |
| 6 | **Helm skeleton.** Chart with Deployment, Service, Ingress, HPA, migration Job (pre-install/upgrade hook), values for external Postgres or CloudNativePG | phase 5 | `helm lint` and `helm template` clean; install into a local cluster if one is available, otherwise state that the install is unverified |

Phase 4 is not named in the `PLAN.md` M0 row, but sign-in and workspace screens have to exist for auth to be usable. It stays minimal: no map UI.

## Out of M0

The map, stories, workflows, the `events` table and real-time sync are M1. M0 migrates only `0001`.
