# M3 — Sharing: phase plan

Scope is the M3 row in `PLAN.md`: public share links, PDF/PNG export, and the roadmap view. Each phase ends in a proof run against the real thing, and the next phase starts from that verified state.

## End state

An editor makes a read-only link to a map and sends it to someone without an account. That person sees the map, can filter it, zoom it, and open a step's details. They see no comments, history, people's emails or edit controls. The link can expire and can be revoked. Everyone can switch a map between the **Map** and a **Roadmap** that lays out each objective's activities across releases with progress and target dates. Both views stay in sync live. Either view can be exported as a PNG or a PDF, as it looks on screen: with its filter, card size, collapsed rows and focus.

## What M2 already provides

- The map payload has everything a read-only view needs: backbone, releases, steps, labels, personas and the workflow. Filters, zoom, collapse and focus work in the browser from it.
- Release bands carry step counts, estimate totals and a done / in progress / blocked meter (`web/src/map/estimates.ts`).
- Tokens are hashed at rest (`auth.NewToken`, `auth.HashToken`), as invites and password resets do.
- `share_links` is sketched in `DATA_MODEL.md`.

## Defaults chosen (change any of these before the phase that uses them)

| Area | Choice | Why |
|---|---|---|
| Who makes links | Editors and up. Any number per map; each has an optional expiry (never, 7, 30 or 90 days) and can be revoked. The list shows who made it, when, expiry and when it was last opened | A link exposes the whole map, so it is an editor's call. Several links let one be revoked without breaking the others |
| Link secrecy | The token is hashed at rest and shown **once**, when the link is made, with a Copy button. A lost link is revoked and replaced | Same as invites and resets; a database leak does not leak working links. The cost is not being able to copy an old link again |
| What a link shows | The map read-only: backbone, releases, steps with title, key, description, status, labels, estimate and personas. Filter, zoom, collapse, focus and the Roadmap work. **Not shown**: comments, history, assignees, member names or emails, saved views, presence | Someone outside the workspace gets the plan, not the people or the conversation |
| Shared page | `/s/{token}`, no sign-in, no nav, `noindex`. Loaded once; a Refresh button reloads it. No live socket | Live needs a socket authorised by the token; read-only viewers rarely need second-by-second updates |
| Roadmap layout | Columns are releases in map order (with target dates), then Unscheduled; rows are objectives with their activities. A cell lists the activity's steps in that release, compact, with the cell's done / total and estimate. A release whose target date has passed with steps not done is marked late | It reads the same data as the map turned into time, so the two views never disagree |
| Roadmap editing | Steps drag between cells as on the map (another release, or another activity), and are added with + Step. Nothing else is edited there | The cells are the map's own, so they behave the same; the backbone and releases stay on the map |
| Export | In the browser: PNG with `html-to-image`, PDF with `jsPDF` as one page sized to the picture (landscape when wide). What is on screen is what is exported: the current view, filter, card size, collapse and focus, in the current theme. Menus, the filter bar and the step panel are left out | No server-side browser to run and keep patched. The CSP blocks inline styles copied from markup, which bit the drag preview; the first step of that phase proves `html-to-image` renders colours under our CSP, and falls back to a print stylesheet (browser "Save as PDF") if it cannot |
| Export from a share link | Allowed | Whoever has the link can see the map anyway |

## Phases

| # | Phase | Input state | Proof |
|---|---|---|---|
| 1 ✅ | **Share links.** Migration with `share_links`; `POST/GET/DELETE /maps/{id}/share-links`; `GET /api/shared/{token}` returning the read-only payload (no assignees, comments or history); a Share dialog in the map header to make, copy, list and revoke links; the `/s/{token}` page with the map, filter, zoom and a read-only step panel | M2 | Go tests: editors only, the token works once shown and only hashed at rest, expiry and revocation answer `404`, the payload leaves out assignees and comment text. Playwright: an editor makes a link, a fresh browser with no session opens it and sees steps and details but no edit controls, comments or names; after revoking, the link shows "not available" |
| 2 ✅ | **Roadmap view.** A Map / Roadmap switch in the map header (kept in the URL); the roadmap grid with per-cell progress and late releases; live updates from the same events; steps drag between releases in their row; the shared page gets the switch too | 1 | Playwright: the roadmap shows steps under the right release and activity, done counts follow a status change made in a second browser, dragging a step to another release moves it on the map too, a past-due release with open steps is marked late, the shared page shows the roadmap |

## Notes

Phase 1:
- Migration `0009` adds `share_links`. Links are not map content, so no events, like saved views.
- `GET /api/shared/{token}` resolves a live, unexpired, unrevoked link on a live map in one `UPDATE … RETURNING` (which also records `last_used_at`), then reads the normal map payload and blanks `assigneeId` and `commentCount`. Comments, history and members have no shared endpoint at all.
- The shared page (`/s/:token`, `web/src/pages/share.tsx`) reuses the map's own header, filter bar, grid and step panel through the map context, with `shared: true`, `canEdit: false` and no-op writes. Components hide what needs a member: saved views, the assignee filter and row, the Comments and History tabs, presence, Activity and Share. The activity ⋯ menu stays, with only Collapse.
- `useMapSearch` and `deriveMap` (in `pages/map.tsx`) are the URL state and derived totals both pages use.
- Buttons on release bands and toasts take the surface's text colour. That override has to live in the utilities layer beside `.btn-ol`; in the components layer it silently lost, which left Focus nearly invisible on the black Unscheduled band.

Phase 2:
- The roadmap (`web/src/pages/roadmap.tsx`) reuses the map's `Cell`, `Meter` and totals, so its steps open, drag, filter and update live exactly as on the map. A release is late when its target date (compared as a local date) has passed with steps not done; the header turns red and its heading says "late". Focus shows one column; collapsed activities show counts.
- The Map / Roadmap switch sits under the map's name and is kept in the URL (`?view=roadmap`), on the shared page too.
- Keyboard moves now compare the centres of targets, not their edges. A cell's edges sit a few pixels outside its cards, so the cell below a card counted as "left" of it (the roadmap's ArrowLeft went down a row) and a cell in the same row could count as "up". On the map, Up from the second card in a cell now always reaches the first card before the release above.

Phase 3:
- `web/src/map/exportView.ts` loads `html-to-image` and `jsPDF` (4.2.1; the 3.x line has published advisories) on first use. The spike passed: html-to-image draws the page into an SVG image that our CSP allows as a `data:` image, and colours survive, unlike the drag preview's copied markup.
- What is exported is the `#map-export` wrapper (`MapCanvas`): the map grid or the roadmap as shown, with a caption (map name, view and date) shown only while exporting. Menus, the + buttons, add slots, collapse toggles and Focus are filtered out. The page's background colour is used, so dark-theme exports stay dark. PNGs are drawn at twice the screen size; the PDF is one page sized to the picture, with `FAST` compression (without it a small map's PDF ran to 4 MB).
- Export as PNG and Export as PDF are in the map header's ⋯ menu, which shared pages now show too, with just those two items.
- The map keeps the width of its widest release band (the flexible last column), so collapsing an activity does not narrow an export; focusing a release does shorten it.

## Out of M3

The public REST API, tokens, webhooks, dependencies and linked maps are M4. Live updates on shared pages, CSV import and export, and embedding a map in another site (an iframe) are not planned.
